# AGENTS.md

Repository notes for agents working on this project.

## What this is

A single-page electrical load list calculator. Rust (axum) serves the calculation API and the built
Vue bundle; Vue 3 + TypeScript + Vite is the UI. One image, one port.

## Commands

```bash
cd backend && cargo test --all-targets      # unit + workbook verification tests
cd backend && cargo clippy --all-targets -- -D warnings
cd frontend && npm run typecheck && npm run build
make build                                  # frontend bundle + release binary
cd backend && STATIC_DIR=../frontend/dist cargo run   # serve built UI on :8080
```

Rust is not preinstalled in a fresh sandbox: `curl https://sh.rustup.rs -sSf | sh -s -- -y` then
`source ~/.cargo/env`.

## Calculation rules (do not "clean up")

The engine must keep reproducing `LOAD LIST.xlsx`. Quirks that look like bugs are intentional:

- Efficiency / power factor for motors interpolate between the 100 %, 75 % and 50 % columns of the
  reference table. The branch below 75 % load factor is selected by **absorbed power > 0.5 kW**, not
  by load factor. Below that, efficiency is extrapolated upward and power factor downward.
- Feeder class → 0.95 / 0.90. Blank or unknown class → "other" → 1.00 / 1.00 (matches the workbook
  cached values). A motor rating missing from the table falls back to 0.95 / 0.90 and raises a warning.
- `FLC = rated kW / (1.732 × kV × η × cos φ)` — the literal 1.732 and the *rated* power are used.
- "Largest load" takes the maximum kW and the maximum kVAr independently, then computes kVA from them.
- Peak load uses 30 % of the *total* intermittent load (no max), while maximum normal running uses
  `max(30 % × total intermittent, largest intermittent)`.
- Items with no duty are excluded from all totals but still counted in `active_items`; the UI flags
  them. This mirrors the workbook, where such rows fall out of every category.
- Total demand = peak × (1 + contingency).

Any change here must keep `backend/tests/workbook.rs` green; those expected values come from the
workbook itself.

## Data model notes

- `EquipmentClass` is `motor | feeder | other`; the workbook leaves some rows blank, which maps to
  `other`.
- `duty` is `Option<Duty>` on purpose (see above).
- Scenario flags come from the `X` markers of the workbook (columns M..R).
- `seed.json` is generated by `tools/extract_seed.py`; never hand-edit it. It is embedded with
  `include_str!`, so a seed change requires a rebuild.
- Runtime state lives in `DATA_DIR/load_list_state.json`, written atomically (tmp + rename).

## Conventions

- Frontend: no UI or chart library — plain Vue SFCs, hand-rolled SVG/CSS bars, design tokens in
  `src/styles.css`. Keep it that way to stay dependency-light.
- The frontend mirrors the calculation in `src/lib/calc.ts` for instant feedback in the drawer. If you
  change `backend/src/calc/`, change both, and keep the server authoritative.
- API JSON is snake_case and matches `frontend/src/types.ts`.
- Mutations refetch `/api/state` (about 500 kB, gzip ~90 kB) so summaries are always consistent.

## Gotchas

- `axum` 0.8 path params use `{id}` syntax.
- The image healthcheck calls the binary with `--healthcheck`; there is no curl in the runtime image.
- `.dockerignore` excludes `*.xlsx`; the seed JSON is committed instead.
- Source workbooks (`LOAD LIST.xlsx`, and future cable-sizing / cathodic-protection files) are inputs
  kept outside the image.

## Releases

Releases are automated with semantic-release (`.releaserc.json`,
`.github/workflows/release.yml`). Never tag or bump versions by hand.

- Commit messages must follow Conventional Commits: `feat:` (minor), `fix:` (patch),
  `feat!:` / `BREAKING CHANGE:` (major), anything else (`docs:`, `chore:`, `test:`, `ci:`,
  `refactor:`) produces no release.
- On push to `main` the workflow writes `CHANGELOG.md`, commits it as
  `chore(release): X.Y.Z [skip ci]`, tags `vX.Y.Z`, opens the GitHub release and pushes the matching
  multi-arch image (`X.Y.Z`, `vX.Y.Z`, `latest`, `sha-*`).
- `.release-version` is a scratch file written by `@semantic-release/exec` so the image job knows
  whether a release happened; it is gitignored.
- `npm ci` at the repository root only installs the release tooling; the app builds from
  `backend/` and `frontend/`.
- Local check without publishing: `npm run release:dry` (needs full history and `GITHUB_TOKEN`).

## Authentication

- `backend/src/auth.rs` owns everything: Argon2 password hashes, HMAC-signed session cookies
  (`eacl_session`, 12 h, HttpOnly, SameSite=Lax), per-IP lockout after 5 failures, and Cap
  verification via `POST <CAP_API_ENDPOINT>/siteverify` with the site secret.
- Credentials live in `DATA_DIR/credentials.json` (0600) as `{username, password_hash,
  session_secret}`. The password itself is never stored: it comes from `AUTH_PASSWORD` or is
  generated once on first boot and logged. `electricacl --reset-password` regenerates it.
- `api::router` splits public routes (`/api/health`, `/api/auth/*`) from protected ones, which go
  through `require_auth` middleware. The SPA shell is intentionally public so the login page loads.
- `CAP_API_ENDPOINT` and `CAP_SECRET` must be set together or not at all; the process refuses to
  start otherwise. Without them the challenge is skipped and the login page says so.
- The frontend bundles `cap-widget` (lazy chunk) so the login page works on an air-gapped network;
  `vite.config.ts` declares `cap-*` as custom elements. It only loads when `cap_required` is true.
- Session state is in `frontend/src/lib/auth.ts`; `api.onUnauthorized` clears it when the API returns
  401, so an expired cookie drops the user back to the login screen.
- HTTP-level behaviour is covered by `backend/tests/auth_http.rs` (401 without cookie, login sets a
  cookie, wrong password rejected, logout clears it).

## UI theme

The interface uses a light copper/orange engineering design language: Inter, white surfaces on
`#f4f6f9`, copper headings (`--copper`), orange gradient primary (`--brand` → `--brand-2`), 10 px
radii, 48 px login controls, split-screen login with a copper/orange branding panel. Keep new
components on those tokens (`frontend/src/styles.css`) rather than adding a UI framework. The app is
branded as "Electrical Calculation Suite" — do not add third-party or customer branding to it.
