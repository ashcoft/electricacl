# AGENTS.md

Repository notes for agents working on this project.

## What this is

A single-page electrical calculation suite: load list (01), cable sizing (02) and cathodic
protection (03). Rust (axum) serves the calculation API and the built Vue bundle; Vue 3 +
TypeScript + Vite is the UI. One image, one port.

## Commands

```bash
cd backend && cargo test --all-targets      # unit + workbook verification tests
cd backend && cargo clippy --all-targets -- -D warnings
cd frontend && npm run typecheck && npm run build
make build                                  # frontend bundle + release binary
cd backend && STATIC_DIR=../frontend/dist cargo run   # serve built UI on :8080
```

Rust is not preinstalled in a fresh sandbox: `curl https://sh.rustup.rs -sSf | sh -s -- -y` then
`source ~/.cargo/env`.

## Calculation rules (do not "clean up")

The engine must keep reproducing `LOAD LIST.xlsx`. Quirks that look like bugs are intentional:

- Efficiency / power factor for motors interpolate between the 100 %, 75 % and 50 % columns of the
  reference table. The branch below 75 % load factor is selected by **absorbed power > 0.5 kW**, not
  by load factor. Below that, efficiency is extrapolated upward and power factor downward.
- Feeder class → 0.95 / 0.90. Blank or unknown class → "other" → 1.00 / 1.00 (matches the workbook
  cached values). A motor rating missing from the table falls back to 0.95 / 0.90 and raises a warning.
- `FLC = rated kW / (1.732 × kV × η × cos φ)` — the literal 1.732 and the *rated* power are used.
- "Largest load" takes the maximum kW and the maximum kVAr independently, then computes kVA from them.
- Peak load uses 30 % of the *total* intermittent load (no max), while maximum normal running uses
  `max(30 % × total intermittent, largest intermittent)`.
- Items with no duty are excluded from all totals but still counted in `active_items`; the UI flags
  them. This mirrors the workbook, where such rows fall out of every category.
- Total demand = peak × (1 + contingency).

Any change here must keep `backend/tests/workbook.rs` green; those expected values come from the
workbook itself.

## Data model notes

- `EquipmentClass` is `motor | feeder | other`; the workbook leaves some rows blank, which maps to
  `other`.
- `duty` is `Option<Duty>` on purpose (see above).
- Scenario flags come from the `X` markers of the workbook (columns M..R).
- `seed.json`, `cable_seed.json` and `cathodic_seed.json` are generated by the `tools/extract_*.py`
  scripts; never hand-edit them. They are embedded with `include_str!`, so a seed change requires a
  rebuild. The extractors fail if their engine no longer reproduces the workbook.
- Runtime state lives in `DATA_DIR/load_list_state.json`, `cable_state.json` and
  `cathodic_state.json`, written atomically (tmp + rename).

## Calculation 03 quirks (cathodic protection)

`backend/src/cathodic.rs` reproduces 23 internal-tank SACP sheets. Do not "fix" these:

- The discrepancy allowance is rounded to 2 decimals *before* it is added:
  `SA = TWA + round(TWA × pct, 2)`, not `TWA × (1 + pct)`.
- The current density uses `(Cd + (T − 25) × 0.001) × CBf`. Some sheets omit CBf; the seed carries
  `apply_coating_breakdown = false` for those.
- The current-density temperature and the anode-capacity temperature are separate inputs because the
  workbook does not always use the same one. `capacity_temp_c` defaults to the operating temperature.
- Four sheets are deliberately excluded from the seed: a partial-shell area formula that omits the
  diameter, a current density that mixes CBf into the temperature term, and a 50 % wetted-area
  allowance. `tools/extract_cathodic_seed.py` reports them as skipped.
- The selected anode count is an input; the engine reports `ceil(M / Aw)` as the requirement and
  flags a shortfall. Some sheets round up to a "nice" number, which is a design choice, not a formula.
- `safety_factor` (S) multiplies the mass balance; it is 1.0 except on the skimmer-tank sheet (1.25).
- ICCP is a current-demand and rectifier-rating calculation, not a workbook reproduction.

## Conventions

- Frontend: no UI or chart library — plain Vue SFCs, hand-rolled SVG/CSS bars, design tokens in
  `src/styles.css`. Keep it that way to stay dependency-light.
- The frontend mirrors each calculation (`src/lib/calc.ts`, `cable.ts`, `cathodic.ts`) for instant
  feedback in the drawer. If you change a backend engine, change its mirror too, and keep the server
  authoritative.
- API JSON is snake_case and matches `frontend/src/types.ts`.
- Mutations refetch `/api/state` (about 500 kB, gzip ~90 kB) so summaries are always consistent.

## Gotchas

- `axum` 0.8 path params use `{id}` syntax.
- The image healthcheck calls the binary with `--healthcheck`; there is no curl in the runtime image.
- `.dockerignore` excludes `*.xlsx`; the seed JSON is committed instead.
- Source workbooks (`LOAD LIST.xlsx`, `0000-EF-D-41335_0 Power Cable Sizing Calc.XLSX` and
  `Basic Cal SACP for Internal Tank - PT Pertamina MOR VII Sulawesi.xls`) are inputs kept outside the
  image. They are tracked in the repository for traceability (PR #4) but `.dockerignore` keeps them
  out of the runtime image.

## Releases

Releases are automated with semantic-release (`.releaserc.json`,
`.github/workflows/release.yml`). Never tag or bump versions by hand.

- Commit messages must follow Conventional Commits: `feat:` (minor), `fix:` (patch),
  `feat!:` / `BREAKING CHANGE:` (major), anything else (`docs:`, `chore:`, `test:`, `ci:`,
  `refactor:`) produces no release.
- On push to `main` the workflow writes `CHANGELOG.md`, commits it as
  `chore(release): X.Y.Z [skip ci]`, tags `vX.Y.Z`, opens the GitHub release and pushes the matching
  multi-arch image (`X.Y.Z`, `vX.Y.Z`, `latest`, `sha-*`).
- `.release-version` is a scratch file written by `@semantic-release/exec` so the image job knows
  whether a release happened; it is gitignored.
- `npm ci` at the repository root only installs the release tooling; the app builds from
  `backend/` and `frontend/`.
- Local check without publishing: `npm run release:dry` (needs full history and `GITHUB_TOKEN`).

## Authentication

- `backend/src/auth.rs` owns everything: Argon2 password hashes, HMAC-signed session cookies
  (`eacl_session`, 12 h, HttpOnly, SameSite=Lax), per-IP lockout after 5 failures, and Cap
  verification via `POST <CAP_API_ENDPOINT>/siteverify` with the site secret.
- Credentials live in `DATA_DIR/credentials.json` (0600) as `{username, password_hash,
  session_secret}`. The password itself is never stored: it comes from `AUTH_PASSWORD` or is
  generated once on first boot and logged. `electricacl --reset-password` regenerates it.
- `api::router` splits public routes (`/api/health`, `/api/auth/*`) from protected ones, which go
  through `require_auth` middleware. The SPA shell is intentionally public so the login page loads.
- CAPTCHA configuration is either `CAP_API_ENDPOINT` + `CAP_SECRET` (public Cap instance) or
  `CAP_UPSTREAM` + `CAP_SITE_KEY` + `CAP_SECRET` (same-origin). In the second mode the app serves
  `/cap/<site-key>/{path}` as a whitelisted reverse proxy to `<upstream>/<site-key>/{path}`
  (`api::cap_proxy`), so the browser never talks to Cap directly and no CORS is needed. Any other
  site key or HTTP method is refused. A partial configuration makes the process exit at startup.
- Without CAPTCHA configuration the challenge is skipped and the login page says so.
- The frontend bundles `cap-widget` (lazy chunk) so the login page works on an air-gapped network;
  `vite.config.ts` declares `cap-*` as custom elements. It only loads when `cap_required` is true.
- Session state is in `frontend/src/lib/auth.ts`; `api.onUnauthorized` clears it when the API returns
  401, so an expired cookie drops the user back to the login screen.
- Sign-out revokes the token: every session carries a `jti`, `Auth::revoke` records it until expiry,
  and `verify_token` rejects it, so a copied cookie stops working immediately. The list is in memory
  only, so a restart forgets revocations (tokens still expire on their own).
- HTTP-level behaviour is covered by `backend/tests/auth_http.rs` (401 without cookie, login sets a
  cookie, wrong password rejected, logout clears it, replayed cookie rejected, security headers).
- The browser-side calculation mirror has unit tests: `cd frontend && npm test` (vitest).

## Cable sizing (calculation 02)

`backend/src/cable.rs` mirrors `0000-EF-D-41335_0 Power Cable Sizing Calc.XLSX`:

- IFLC uses `1.732` for three-phase and `1` for single-phase; the voltage drop uses `1.732` / `2`.
- `IZ = It × Cg × Ca`; `It`, `R` and `X` come from the reference table keyed by `(cores, size_mm2)`.
  A size that is not in the table yields `IZ = 0`, a `cable_not_in_table` warning and a failed check.
- Circuits sharing a `group` are a **series chain**: the first circuit reports the cumulative
  `%VDlast` and the chain length, the others report `None`. A circuit with no group is its own chain.
- The source workbook's `AK15` (max length of SI 1) references the next row's allowable drop and uses
  the single-phase factor for a three-phase circuit; the engine uses the circuit's own limit and
  1.732 (95.7 m instead of 248.5 m). Both pass the 25 m check, so the verdict is unchanged. This is
  the only intentional deviation and is documented in `tools/extract_cable_seed.py`.
- `tools/extract_cable_seed.py` regenerates `backend/data/cable_seed.json` and fails if any of the 10
  circuits no longer matches the workbook; `backend/tests/cable_workbook.rs` asserts the same numbers.

## PDF report

`backend/src/report.rs` renders the A4 report with `printpdf` and the base-14 fonts (Courier for
tables, Helvetica for headings), so the file stays ~200 kB and needs no font files or browser.
Tables are laid out with **character-based column widths** (`Column { chars }`) and a monospaced
font; adding a column means adding a `Column` entry and one value per row, and keeping the total
under ~130 characters at 6.5 pt. `ascii()` folds typographic characters into WinAnsi-safe text.
Tests in `backend/tests/report.rs` parse the output with `lopdf` (page count, document title).

## UI theme

The interface uses a light copper/orange engineering design language: Inter, white surfaces on
`#f4f6f9`, copper headings (`--copper`), orange gradient primary (`--brand` → `--brand-2`), 10 px
radii, 48 px login controls, split-screen login with a copper/orange branding panel. Keep new
components on those tokens (`frontend/src/styles.css`) rather than adding a UI framework. The app is
branded as "Electrical Calculation Suite" — do not add third-party or customer branding to it.
